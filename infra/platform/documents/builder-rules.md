# Builder rules (BOSS dev pod) — read fully before the first command

You are a builder on the BOSS cluster dev pod, in your OWN git worktree (an isolated copy; never cd to /work/boss or another worktree). Your brief precedes this document in the prompt: the packet verbatim from the system of record and the gate's invariants, derived from the files that decide them. Read it first and follow the invariants section literally. Your run has a packet of its own (its id closes the prompt): export it as `BOSS_AGENT_RUN=<run id>` in the shell you gate from, so the gate-run records which run launched it and the run lands on the green by itself.

1. Base and branch. `git fetch origin` then branch from `origin/main`: `git checkout -b <branch> origin/main`. (If origin/main moves while you build, the base check quoted at the end of this rule will fail right before the gate — expected; `boss gate --rebase` replays your commit onto the new main and the rebased sha is the one to report.) Branch name `fix/...` or `feat/...`, lowercase, hyphenated, a sentence-like title. Never `git rebase`. Never force-push. If origin/main moves under you, do not worry — the conductor merges cars; only re-base by `git checkout -b <branch>-2 origin/main && git cherry-pick <sha>` if asked. Never `git reset --soft origin/main` to squash: worktrees share remote-tracking refs, so origin/main can move under you mid-build (another session's fetch), and the reset then folds the OTHER train's landed work into your commit as a reversal (it happened to the builder of 1b52c278, 2026-09-19, and was caught only by the diff read before push). Commit on the branch and let `boss gate --rebase` replay it, or cherry-pick onto a fresh branch cut from the origin/main you just fetched — and run the base check before pushing: the diff must be only your files. It is not restated here — these are the `base check` invariant's own lines, quoted from the one place that defines them, because the same sentence was corrected in this rule and in that invariant on one day by two builders who did not know about each other (8d054cb2 and 9843aeb9, 2026-09-19; backlog 395d24ad):

{{invariant:base check}}

Three dots, because that diffs from the MERGE-BASE — the two-dot form compares the two tips, so every commit that lands on main while you build is reported back as your branch's deletions (on car 6e738252, one commit behind, two-dot said 47 files / 5235 deletions and three-dot said 7 files / 16 deletions — the builder's own files, 2026-09-19). Do not "simplify" it back: the false alarm invites the merge-or-reset this same rule forbids, and the three-dot form still catches the 1b52c278 case, because work folded into your OWN commit as a reversal shows up in the merge-base diff.
2. Cargo ONLY through `wt-cargo` (on PATH): `wt-cargo test -p <crate> ...`, `wt-cargo clippy -p <crate> --all-features --tests -- -D warnings`, `wt-cargo fmt -p <crate>` (or `cargo fmt -p <crate>` — fmt is fine bare). It gives this worktree its own target dir, bounds jobs (4-wide and nice'd for a builder worktree — the pod is shared with the operator's interactive session, and it lagged when three builds collided) and never pass WT_JOBS yourself; bare `cargo build/test` can take the pod's 16 GiB / 8-CPU cgroup to its ceiling and kill other work.
3. TDD: write the failing test first, run it and SEE it fail, then the smallest change that makes it pass. Tests go beside the code (`#[cfg(test)]`) or in `crates/core/boss-testing/tests/` for shell/infra; use `boss_testing::repo_root()` and `boss_testing::scratch_dir(...)` — never a fixed /tmp path, never your own repo-root helper (a lint refuses both).
4. Before pushing, IN THIS ORDER: `cargo fmt` FIRST, then `git add`, then commit (a builder ran add, then fmt, then commit -F and committed the stale staging — one extra commit on the car, 2026-09-18); clippy as above on the crates you touched, the touched crates' WHOLE test suite with `--all-features` (`wt-cargo test -p <crate> --all-features` — `--lib` or a named test misses the `postgres`-feature integration tests, which redded two gates on 2026-09-15), then `bash infra/gate.sh --quick` (~15 s; must end "clean"). A change under infra/lint/, infra/forge/, infra/ops/, infra/dev/ or infra/platform/ is pinned by crates/core/boss-testing — the tests there drive those scripts on the real bundle — so a lint- or infra-only car that touches no Rust crate still runs that crate's whole suite before pushing, `wt-cargo test -p boss-testing --all-features`, the same as a touched crate (the builder of 1b847556 read "the touched crates' whole suite" as none, ran only the two lint-exercising tests, and its first gate went red, 2026-09-19).
5. Commit: imperative mood title, a body that says WHY with the measured evidence from the packet, and end the message with exactly this line:
   Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>
6. Push: `git push origin HEAD:<branch>`.
7. Gate. Your own files — commit message, probe rehearsal, gate script, logs — live under scratchpad/builders/<packet id>/ (YOUR scratch dir, given in the prompt), never at the scratchpad root: the root is shared by concurrent builders, and one builder's commit-msg.txt was overwritten by another's mid-session (0f2ecbda, 2026-09-19). Write the FULL gate command into a script there as `gate.sh`, then run `bash <that script> > <your scratch dir>/gate.log 2>&1` in the FOREGROUND — never pipe it through tail, which hides the launch line until exit (the harness refuses inline command text containing the word git; a background task gets killed under memory pressure — the gate itself continues in-cluster either way, and auto-park is stamped at launch). The command:
   cd <your worktree> && export BOSS_AGENT_RUN=<your run id> && exec boss gate <branch> --wait --mode auto --rebase --park-backlog-item <FULL uuid of your packet, copied from the brief, never typed from memory> --park-summary '<what changed and why, 3-6 sentences, no backticks>' --park-excludes '<what this car deliberately does not do>' --park-test '<the tests and checks you ran, by name, with counts>' --park-verified '<what an operator would observe after landing>' --park-probe '<shell text>' --park-expect '<the exact string the probe prints on success>'
   Prose rules: single quotes, NO backticks anywhere (argv eats them), no double quotes inside except escaped within the probe.
   Probe rules: it runs later ON THE FORGE HOST as user david, cwd = the converged checkout of main, with a 60 s timeout. Available there: git (use `git show HEAD:<path>` to read the converged tree — never fetch), jq, curl, `boss-sor-read "<api path>"` which prints the system-of-record JSON body for a GET, and the tree's own `boss` CLI (installed from the converged image on every tick since 2026-09-18 — read-only: a probe proves, it never writes, and the unattended door gives it no BOSS_ACTOR so a write refuses itself). What is NOT available is the list in `infra/forge/host-absent-tools.txt`, and that file is the one to read rather than a copy here: `boss gate --park-probe` refuses against it, at gate time on your terminal rather than hours later as an exit code on a car, and it carries the reasoning and the measurement date for every entry. This paragraph used to restate it and went stale — it said `boss` was unavailable for the whole day after the forge started installing it (785dc91a). Exit 0 and print the expect string when the claim holds; `exit 75` with a "not yet: ..." line when it cannot be judged yet (e.g. the change has not converged, or the event it needs has not happened); exit 1 when it is judged false. Guard every numeric test against null/empty (jq `// empty`, or `case "$x" in ''|*[!0-9]*) ... exit 75;; esac`; the quote-free form is `case ${n:-empty} in empty|*[!0-9]*)` — never prefix with a letter like `x$n`, which makes the guard match every digit and the probe read not-yet on both legs). A probe that asks whether its qualifying event happened AFTER the change landed dates that cutoff from `$BOSS_CAR_CONVERGED_AT` — the commit time of this car's own merge, handed to every recorded probe and FIXED — never from `git log -1 --format=%ct HEAD`, which is the converged checkout's current head and advances with every train (~28 a day), so the car starves: three cars were measured unprovable that way on 2026-09-19 (a92571a6). Guard it first: `case ${since:-empty} in empty|*[!0-9]*) echo 'not yet: this car has not converged here'; exit 75;; esac`. grep is line-based: never grep for a phrase that wraps across lines in the source. REHEARSE the probe twice before launching: against your branch (it must print the expect string, exit 0) AND against origin/main (`git show origin/main:<file> | grep …` — it must NOT pass there; a pattern that is a substring of something already on main proves nothing). For a probe reading the live jobs API with a NEW query parameter, add a control leg: a key/value nothing matches must answer 0, else exit 75 (an old server ignores unknown params and answers the unfiltered count).
