# infra/cluster/instance-manifests.txt — WHICH manifest under
# infra/cluster/manifests/ exists once per INSTANCE and which exists once
# for the PIPELINE (backlog 07d7549c car 1; design ffc83387, decided by
# David 2026-09-16: playground.algedonic.dev is a second namespace on the
# current cluster, and both prod and the playground converge on every
# train).
#
# infra/cluster/render-instance.sh reads this file. It renders every
# `instance` manifest once per entry in infra/cluster/instances.toml —
# the directory IS the prod instance, and an instance is that directory
# with four parameters substituted (namespace, tenant manifest, sim
# flag, public hostname) plus the namespace-scoped DNS names — and it
# copies every `pipeline` manifest once, as written, into prod's render.
# A manifest in the directory that this file does not classify REFUSES
# the render, by name; so does an entry here with no file behind it, or
# a file in both sets. crates/core/boss-testing/tests/render_instance_sh.rs
# reads this file independently and pins the same three facts (CLAUDE.md
# §9a: a fact that lives twice gets an equality test). Adding a manifest
# is therefore two lines: the file, and its line here.
#
# One line per manifest: `<basename> <set>`; a comment starts with `#`.
# The `why` for each entry is the comment above it — the classification
# is a decision, and a decision without its reason is the kind of line
# that gets flipped by the next person who reads only the table.
#
# WHAT `instance` MEANS. The object holds state or serves traffic for ONE
# BOSS instance: its Postgres and NATS, the boss Deployment (carrying
# its public hostname as BOSS_PUBLIC_URL) and its Services, and the
# chores that maintain ITS database and open their packets on ITS jobs
# door. Rendered per
# instance; each instance gets its own PVCs through the StatefulSets'
# volumeClaimTemplates and its own PersistentVolumeClaims.
#
# WHAT `pipeline` MEANS. The object runs the trains and gates, or is
# pinned to prod for a stated reason: it exists exactly once, in prod,
# exactly as the file says. The conductor, the dev pod and its access,
# the credential broker, the gate seed, break-glass — and three
# instance-SHAPED objects held back for the reasons on their lines.

# --- instance: rendered once per entry in instances.toml ----------------

boss.yaml instance

# There is no TLS front per instance. Until 2026-09-17 boss-tls-front.yaml
# (Caddy terminating the instance's hostname with a lego-issued
# `boss-tls` Secret) was rendered here, and every instance whose
# namespace lacked that Secret was SKIPPED on every converge — the
# playground, from the day it was declared. Let's Encrypt left the
# cluster with backlog 21c17ebc (design 4c565f8c, David 2026-09-16):
# Cloudflare terminates TLS at the edge and the tunnel connector
# (cloudflared.yaml, a pipeline manifest below) proxies each instance's
# hostname straight to its gateway Service in plain HTTP. The hostname
# parameter now lands only on the boss Deployment's BOSS_PUBLIC_URL.

boss-conductor.yaml pipeline
boss-dev.yaml pipeline

# The break-glass ceremony is the business system of record's; the
# boss pod mounts this ConfigMap `optional: true`, so an instance
# without one boots and answers 409 "no credential enrolled".
boss-break-glass-credentials.yaml pipeline

# The Cloudflare Tunnel connector (backlog 5a2bb0ce; design 4c565f8c,
# David 2026-09-16): ONE tunnel, in prod, serving EVERY instance — its
# config names each instance's hostname and gateway Service by
# namespace (rendered from instances.toml by render-tunnel-config.sh),
# and its credentials are one Secret minted once. Rendered per instance
# it would start a second connector per namespace on the same tunnel
# credentials, each routing every hostname; that is not two instances,
# it is one tunnel twice.
cloudflared.yaml pipeline
cloudflared-config.yaml pipeline

# Instance-shaped, held in prod for a reason each:
#
# boss-estate-observe: observes the ESTATE — every node, every
# namespace, the gate Jobs in boss-dev — and files what it sees into the
# system of record. One estate, one observer; and its ClusterRole /
# ClusterRoleBinding are cluster-scoped names a second render would
# collide on.
boss-estate-observe.yaml pipeline
#
# boss-playground-crawl: crawls ONE instance — the playground, by its
# Service name — and files its packet on prod's jobs door, so it is
# instance-shaped; but it runs in boss-dev because the forge is not
# anonymously readable and the clone it needs uses `forge-read`, the
# pipeline namespace's credential (the gate runner's). Rendered per
# instance it would run once per namespace, each against the same
# target, each without the credential (design 0e07ce64, 2026-09-18).
boss-playground-crawl.yaml pipeline
#
# boss-backup: the nightly dump ships to boss-gcp and to GCS under the
# name `boss-<stamp>.sql.gz` with a keep-21 retention shared by every
# dump in the bucket. A playground dump under the same name would spend
# prod's retention (21 nights becomes ~10), and the playground is
# reproducible from examples/brewery/seeds plus the sim. A per-instance
# backup that names its dumps by instance is its own car.
boss-backup.yaml pipeline
