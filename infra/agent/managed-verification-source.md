# BOSS managed cache verification and renewal

This is source preparation for urgent3869107c and accepted6f3ef63c. The
native ScopePort, private collector/channel, genuine enrollment, provider
effect and publication/recovery are still uninstalled or unproved. This
engine does not enable a native launch or write a Ready generation.

The private async engine independently verifies managed ID tokens with the
fixed OpenAI issuer, native0.159.3 client audience, RS256 public signing keys,
expiry/issued-at/not-before bounds and the broker's enrolled stable subject
and workspace. Cached email, plan, a parsed unsigned claim and login status
are not identity evidence. Authenticated userinfo must confirm the access
token's actual subject too. Missing, expired or incompatible inputs refuse;
this is a conservative source contract, not a claim every managed cache has
already been qualified under it.

Opaque refresh tokens cannot be certified by an ID signature or userinfo.
Renewal is therefore an explicit async rotating effect. After an independently
attested held lease, incarnation, stopped writer and retained mount, the
descriptor-confined store records the complete private input and refresh
intent durably before a provider request. The protected provider adapter uses
the pinned native refresh operation. It retains private status/body/EOF
originals before interpretation, requires new ID/access/refresh tokens and a
fresh independently verified ID subject matching the enrolled principal,
then checks the replacement access token through authenticated userinfo.
The complete replacement cache is durably retained before a proof exists.

A hash/run/nonce/subject-bound witness enters the existing synchronous
FileStore callback. That callback returns the qualified replacement bytes;
the collector conserves those bytes instead of the input's now-spent refresh
token. Reconciliation verifies the same retained replacement and keeps the
stream Collected/unavailable. There is no publication, Ready or unlock door.
An uncertain effect, incomplete/missing response, changed principal or
durability failure quarantines the stream where possible and never makes it
available. A retained refresh intent refuses a repeated effect; exact
recovery and dedicated re-enrollment remain separate obligations.

The HTTP adapter has fixed HTTPS endpoints, no caller URL/issuer/client
override, no proxy or redirects, and bounded connection/operation time.
Responses are capped at64KiB; an oversized/interrupted body is retained as an
explicit incomplete private original and cannot qualify. No private value
is passed through argv, journaled Kubernetes Exec, public metadata, errors,
attachments or diagnostic serialization. Only private storage receives the
input, response and replacement. All filesystem work runs on the blocking
pool; provider I/O is awaited outside it. No provider request was made in
source validation: keys/tokens/effects are synthetic fixtures and request
construction is checked without sending it.

Current published input terms come from:

- [Pinned0.159.3 native manager](https://github.com/openai/codex/blob/01fc69f4026735edfdf6789820549727a4867b11/codex-rs/login/src/auth/manager.rs): native client ID and managed JSON refresh operation at `https://auth.openai.com/oauth/token`.
- [Public issuer discovery](https://auth.openai.com/.well-known/openid-configuration): issuer, RS256/JWKS and authenticated userinfo endpoint. Its different token endpoint is not silently substituted for the pinned operation.
- [Official identity verification](https://developers.openai.com/siwc/website): independent signature/issuer/client/expiry and stable-subject checks. This engine does not register a new token-sharing client or replace the accepted managed enrollment flow.

Before installation, native evidence must establish the actual managed token
claims and provider endpoint compatibility, enrolled issuer/client/subject
and workspace, collector/mount/scope, protected durable originals and
acknowledgment. A synthetic source gate supplies none of these facts.
